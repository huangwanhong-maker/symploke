# 2026-11-15

## JSON-LD

Linked data written as JSON is now read and written, so web pages, IIIF manifests and Web Annotations become statements ([decision 0004](../decisions/0004-json-ld.md)):
- documents are expanded by the W3C's JSON-LD 1.1 algorithms and turned into RDF, every keyword of the language handled, from scoped contexts and protected terms to every kind of container;
- remote contexts are given by the caller, never fetched; one not given is refused, naming it, so that the caller can fetch it and ask again;
- datasets are written compacted against their prefixes;
- errors carry the API's codes, and the line and column of the value at fault;
- JSON is read and written canonically (RFC 8785).

Every document of the checks reads into the statements pyld, the reference implementation, gives for it; every document pyld refuses is refused with the same code; datasets are written as pyld compacts them, and read back unchanged.

## symploke Founded: Linked Data

symploke holds what linked data needs, whatever it describes:
- RDF's terms, with the values of their literals;
- N-Triples, N-Quads, Turtle and TriG, read exactly or refused with line and column, and written back;
- a store indexed every way whose edits each come with their undo;
- queries in SPARQL's core: patterns, OPTIONAL, UNION, MINUS, FILTER, BIND, VALUES, GRAPH, property paths, aggregates, ordering;
- entailment by RDFS and a part of OWL 2 RL, each conclusion with its derivation, inconsistencies reported;
- SHACL Core, with every failure named;
- graphs compared up to the names of their blank nodes.

It was founded at the user's request for RDF in the digital humanities ([decision 0002](../decisions/0002-scope-boundaries-and-dependencies.md)).
